# Scenarij M0.6 — ponovljiv testni svet

**Namen:** imeti svet, ki ga katerakoli seja postavi znova z istim rezultatom, in v katerem
so NPC-ji za reprodukcije R1 in R2 ter za meritve M2 vedno na istem mestu z istimi nastavitvami.

**Vhodni pogoj:** M0.5 (dedicated server preverjen).
**Kdo to potrebuje:** M2 v celoti. Brez tega meritve niso primerljive med sejami.

---

## Zakaj superflat in ne generiran svet

Generiran svet je odvisen od terena: NPC na hribu se obnaša drugače kot NPC v dolini,
pathfinding ima drugačno ceno, render drugačno število blokov. Superflat z fiksnim
seedom odstrani to spremenljivko, ovire pa postavimo sami z `fill`, zato so **znane in
enake pri vsaki ponovitvi**.

Determinizem dodatno zagotavljajo: izklopljen daljni cikel in vreme, brez pošasti in živali,
`randomTickSpeed 0` (brez rasti in razpadanja blokov), brez struktur, fiksen čas dneva.

## Kaj sestavlja svet

| Element | Koordinate | Namen |
|---|---|---|
| tla superflat | y=3, entitete stojijo na y=4 | konstantna podlaga |
| world spawn | `0 4 0` | fiksna izhodiščna točka; konzola izvaja ukaze na `(0,0,0)` |
| stena | `x=20`, y=4–12, z=-8..8 | ovira za R2: leteči NPC mora čeznjo |
| dve pregradi | `z=20` in `z=36`, x=-8..8 | koridor za R1: nosilec z jahačem gre od ene do druge |
| 8 fixture NPC-jev | `(0..8, 4, 0)` in `(0..8, 4, 8)` | glej `dev/testworld/README.md` |

## Postopek

```powershell
# 1. postavi svet (star svet se arhivira, nic se ne brise)
.\testworld.ps1

# 2. zazeni server
.\dev.ps1 runServer --offline
```

```
# 3. v server konzoli prilepi vsebino dev\testworld\setup-commands.txt

# 4. preveri prizorisce
noppes clone list 1
execute @e[tag=testworld] ~ ~ ~ say TW-OK

# 5. ustavi server
stop
```

```powershell
# 6. samodejno ovrednoti merila W1-W8 iz loga in datotecnega sistema
.\verify-testworld.ps1
```

Za W6 (preživetje restarta) se koraka 2, 4 in 5 ponovita **brez** `testworld.ps1` in brez
ponovnega lepljenja `setup-commands.txt`, nato:

```powershell
.\verify-testworld.ps1 -Restart
```

Ponovitev prizorišča v istem svetu brez ponovnega generiranja:

```
kill @e[tag=testworld]
```
nato znova prilepi del `setup-commands.txt` s `noppes clone spawn`.

## Merila sprejemljivosti

`verify-testworld.ps1` preveri vsa merila samodejno in vrne izhodno kodo 0 ali 1.

| # | Kriterij | Kako se dokaže |
|---|---|---|
| W1 | seme vsebuje natanko 8 fixture NPC-jev | `dev/testworld/customnpcs/clones/1/*.json` |
| W2 | server pripravi svet brez izjeme | `Preparing level "world"` v logu |
| W3 | `noppes clone list 1` izpiše vseh 8 imen `T_*` | log |
| W4 | vseh 8 NPC-jev je v svetu: `TW-OK` se izpiše **8×** | log |
| W5 | skripta na `T_Scripted` se **dejansko izvede**: `TW-SCRIPT-OK` ≥ 1× in nobenega `script errored` | log |
| W6 | po `stop` in ponovnem zagonu W4 in W5 še vedno veljata | log drugega zagona, `-Restart` |
| W7 | `dev/run/world/customnpcs/clones/1/` ima ≥ 8 datotek, brez `.tmp` in `.bak` | datotečni sistem |
| W8 | v logu ni `ERROR` vrstice, ki omenja `noppes` | log |

### Zakaj je W5 pozitiven dokaz, ne odsotnost napake

Prvotna oblika merila ("skripta ne vrže napake") je bila past: če scripting sploh ne teče,
napake ni in merilo lažno uspe. `DataScript.isEnabled()` zahteva **tri** stvari hkrati —
`ScriptEnabled` v NBT NPC-ja, `ScriptController.HasStart` (postavljen šele ob
`FMLServerStartedEvent`) in `CustomNpcs.EnableScripting` iz configa. Zato mora merilo
zahtevati **izpis iz same skripte**.

`T_Scripted` zato v `init` požene `/say TW-SCRIPT-OK`. Ukaz teče prek
`NPCWrapper.executeCommand`, ki zahteva vklopljene command bloke — `server.properties` v
semenu ima `enable-command-block=true`. Izhod `/say` gre v server konzolo tudi brez
prijavljenega igralca, zato je merilo preverljivo iz loga.

Dodatno `tick` po 200 klicih izpiše `TW-SCRIPT-TICK-200`. To ni merilo sprejemljivosti,
ampak poceni dokaz, da scripting teče še naprej in ne le ob inicializaciji; uporabno pri
M5, ko se bo odstranjeval globalni script lock (`ScriptContainer.run` sinhronizira na
statičnem `lock` objektu za **vse** NPC-je).

Če W5 pade, se `T_Scripted` **ne** umakne iz semena — najprej se preveri
`noppes config scripting` in ali je engine sploh registriran (`Script Engines Available:`
v logu ob zagonu). Šele če scripting v okolju ni na voljo, se to zapiše v `04-STANJE.md`
kot blokada za M6; ostalih sedem fixture NPC-jev je od njega neodvisnih.

## Kaj ta paket namenoma **ne** vsebuje

- **Quest fixture.** Questa ni mogoče zanesljivo sestaviti brez GUI-ja, ugibanje NBT
  strukture pa je točno tisto, kar protokol prepoveduje. Quest nastane v M0.7: uporabnik
  ga enkrat naredi v GUI-ju, nato se `world/customnpcs/quests/` posname v `dev/testworld/`.
- **Dialog, pripet na NPC-ja.** Privzeti `Villager` dialogi 1–3 nastanejo sami ob prvem
  zagonu in so v svetu prisotni; vezava dialoga na fixture NPC-ja gre skozi GUI, zato je
  tudi to M0.7.
- **Meritve.** Scenariji za 50/200/500 NPC-jev so M2.4. Seme zanje ponuja
  `noppes clone grid <ime> <tab> <dolzina> <sirina> [x,y,z]`, kar je dovolj za mrežo.
