# M0.5 — Dedicated server smoke test

**Namen:** dokazati, da se dedicated server zažene s popravljenim dev runtime jarjem,
da se da NPC ustvariti, da preživi `save-all` in restart in da se po restartu prebere
z enako NBT vsebino.

**Ponovitev:** `.\smoke-server.ps1 -AcceptEula` iz korena mape.
Vsi izpisi gredo v `audit\m05-server-smoke.log` (povzetek) ter
`audit\m05-server-a.log`, `-b.log`, `-c.log` (polni server logi).

## Zakaj trije zagoni in ne dva

`CommandSummon` v 1.12.2 javi `Cannot summon the object out of the world` tudi takrat,
ko **ciljni chunk ni naložen**, ne samo pri neveljavnih koordinatah. Spawn superflat
sveta lahko pade do 256 blokov od izhodišča, zato chunk `0,0` ni nujno med spawn chunki.
Prvi zagon zato samo pribije world spawn na `0 5 0`; po restartu so ti chunki zajamčeno
naloženi.

Stranski učinek je natanko to, kar potrebuje **M0.6**: determinističen testni svet z
znanim spawnom.

`execute … say` je izbran namesto `testfor`, ker konzola izpiše **ime NPC-ja v oklepaju**:
`[SmokeNPC] M05-NPC-PRESENT`. En sam marker s tem dokaže troje — entiteta obstaja, je
pravega tipa in NBT ključ `Name` je preživel round-trip skozi popravljeno save pot.

## Kako server sploh sprejme ukaze

Gradlov `JavaExec` privzeto poda prazen standardni vhod, zato je konzola dev serverja
brez popravka mrtva in ga ni mogoče niti čisto ustaviti. V `dev/build.gradle`:

```groovy
afterEvaluate { tasks.getByName('runServer').standardInput = System.in }
```

Deluje **samo z `--no-daemon`**, ker mora biti `System.in` resnični vhod procesa.
Skripta zato poganja `gradlew.bat runServer --offline --no-daemon --console=plain`.

# Dodatek — ročna različica s clone shrambo (11. 9. 2026)

Skriptirani test zgoraj dokaže `summon` → save → restart. **Ne pokriva pa clone shrambe**
(`noppes clone add/list/spawn`), ki jo je popravil M1.5a. Ta ročni postopek je bil izveden
11. 9. 2026 na prvi delovni postaji in je pokril prav to; ohranjen je, ker so njegova merila
C3, C4 in D1 edini dokaz, da clone JSON preživi restart.

Ko bo `smoke-server.ps1` razširjen še na clone shrambo, ta dodatek odpade.

**Namen:** dokazati, da se `runServer` zažene, da NPC preživi `save` + restart, in da
clone shramba (popravljena v M1.5a) preživi restart.

**Izhodni kriterij M0.5 iz `03-FAZE.md`:** `runServer` se zažene, NPC preživi save + restart.

**Zakaj so koordinate take:** ukazi iz server konzole se izvajajo na poziciji `(0, 0, 0)`
(`MinecraftServer.getPosition()` vrne `BlockPos.ORIGIN`), `/noppes clone add` pa išče NPC-je
v radiju 80 blokov od pošiljatelja. NPC zato spawnamo na `(0, 72, 0)`, ne na world spawnu
`(132, 64, -32)`. Chunk `(0,0)` je znotraj naloženih spawn chunkov, zato entiteta ostane
naložena in se shrani.

**Zakaj `Invulnerable` in `NoGravity`:** NPC ne sme umreti zaradi terena, vode ali padca,
sicer test meri napačno stvar.

**Registry ime entitete:** `customnpcs:CustomNpc` (`CustomEntities.registerNewentity`,
`new ResourceLocation("customnpcs", name)`) — velike in male črke so pomembne.

---

## Faza A — v že tekoči server konzoli

```
summon customnpcs:CustomNpc 0 72 0 {Name:"SmokeM05",Invulnerable:1b,NoGravity:1b,Tags:["m05"]}
execute @e[type=customnpcs:CustomNpc] ~ ~ ~ say M05-PRESENT
noppes clone add SmokeM05 1
noppes clone list 1
save-all flush
stop
```

Pričakovano: `M05-PRESENT` natanko enkrat, `noppes clone list 1` izpiše `SmokeM05`,
`save-all flush` konča brez napake, `stop` se konča brez izjeme.

## Faza B — restart

```powershell
.\dev.ps1 runServer --offline
```

## Faza C — v novi server konzoli

```
execute @e[type=customnpcs:CustomNpc] ~ ~ ~ say M05-SURVIVED
execute @e[type=customnpcs:CustomNpc,tag=m05] ~ ~ ~ say M05-TAG-OK
noppes clone list 1
noppes clone spawn SmokeM05 1 0,74,0
execute @e[type=customnpcs:CustomNpc] ~ ~ ~ say M05-AFTER-CLONE-SPAWN
save-all flush
```

## Faza D — neobvezno čiščenje

```
kill @e[type=customnpcs:CustomNpc]
noppes clone del SmokeM05 1
```
