# M6.4 — loader na NPC/tab/generacijo, bytecode cache, atomski reload

2026-10-29 · seja 173 · **zaključen, poskus 1**. Vhodni commit `e521c14`.
Teste, build in Minecraft zaganja controller.

## Izvedba in meje

- `rework/script/BytecodeCache`: omejen LRU (64 vnosov, 16 MiB) **samo bajtov** — ne razredov,
  loaderjev, instanc ali MethodHandle. Ključ SHA-256 (dolžinsko predponjeni deli): identiteta
  prevajalnika + JVM verzija + opcije, classpath in odtis vsakega vnosa (velikost + mtime), urejene enote.
- `JdkScriptCompiler`: `identity()` in `newLoader(bajti, parent)`; opcije nespremenjene.
- `JavaNpcScripts`: ena **generacija na handler** (vsi tabi NPC-ja). Vsak tab dobi lasten loader
  (parent = API loader) in instanco iz bajtov, zato static stanje ne prehaja med NPC-ji, tabi ali
  generacijami. Nova generacija ob `lastLoaded`, spremembi taba/vključitve ali novih containerjih
  (GUI save, kot nov JS engine); pripravi se cela pred dogodkom in zamenja samo, če se vsi tabi
  prevedejo, vežejo in instancirajo. Sicer teče zadnja veljavna generacija, konzola taba
  »Reload rejected…« z napako, tab ni `errored`; nespremenjen pokvarjen vhod se ne prevaja ponovno.
  Brez veljavne generacije se nič ne izvede, pokvarjen tab je `errored` (pogodba M6.2).
- `DataScript`: en klic `run(tabs)` na dogodek. JS pot in `ScriptContainer` nespremenjena.
- Ni še: `errored` po runtime napaki ostane do GUI save (B5, M6.5); cache ni persistenten (po
  restartu JVM prvi dogodek prevaja); dev imeniški vnos classpatha šteje samo mtime imenika.

## Odločitve

**Q151 — enota atomskega reloada:** handler (vsi tabi NPC-ja), ne posamezen tab; novi containerji
(GUI save) so nova generacija. Razlog: Q130 »celotna nova generacija handlerja«; tabi si delijo
dogodek in preklic, mešanica stare in nove generacije bi dala nekonsistenten vrstni red.
**Q152 — neuspeh reloada:** zadnja veljavna generacija teče, napaka v konzoli taba in OP obvestilo,
brez `errored`; brez veljavne generacije se nič ne izvede in tab je `errored` (kot M6.2/M6.3).
Razlog: Q130; ohrani preverjeno pogodbo M6.2 za prvi neuspeh.
**Q153 — cache:** statičen LRU 64/16 MiB samo bajtov s ključem iz Q130 + JVM verzija in odtis
velikost/mtime vsakega classpath vnosa. Razlog: brez deljenja živega stanja; zamenjan API jar
invalidira brez branja celotnih jarjev ob vsakem prevodu.
**Q154 — save/restart:** dokaz po poti chunk NBT (`writeToNBTOptional` → `EntityList.createEntityFromNBT`)
v tekočem strežniku, ne tretji zagon strežnika. Razlog: loaderji in cache po zasnovi ne preživijo
JVM; obstane samo NBT, in to je ista pot kot shranjevanje/nalaganje sveta. Omejitev: pravi restart s
Java NPC ni posebej izveden.
**Q155 — testi:** unit/build/package, `m64-packaged-v1` in regresiji `m62-packaged-v2`,
`m63-packaged-v1` (produkcija spremenjena); brez dev zagona (Q149) in brez cene.
