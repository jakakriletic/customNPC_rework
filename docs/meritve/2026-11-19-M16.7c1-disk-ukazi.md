# M16.7c1 — diskovni adapter in ukazi

**Stanje: c1 sprejet 19. 11. (Q550).** Dedicated `m167c1-workspace-v4` PASS na
`be9add35a8148086cb26ee17ed688a54dfe7742e6f1c1bc71782e2e0f0176e74`: **178 preverb**,
fazi 0/1 po 35/35 in restart 13/13. Controller je prej opravil
unit/build/package na `471bc04969404ade1e62324558439e8370e979b091991a03700b0c2445599bf9`.
Scenarij v1 je padel pri pripravi ticking pogoja (Q547), v2 pri Nashorn permission
adapterju (Q548), v3 pri PowerShell sestavljanju pričakovanih ključev po restartu
(Q549). Popravljen samo harness; produkcija in JUnit vhodi ostajajo
nespremenjeni. Rezultati ostajajo vezani vsak na svoj zapisani odtis; starih rezultatov
ne pripisujemo novemu odtisu. Po uspešnem v4 so spremenjeni samo zaključni dokumenti.

Pogodba: [M16.7c0](../raziskave/M16.7c0-pogodba-mape-klona.md), D-108, Q542–Q544.
`CloneWorkspace` neposredno obdeluje NBT. Izvoz vsebuje clone v1, strog manifest,
vse pravilno tipne kartice ter točen Clips niz. UTF-8 je strog, brez spreminjanja vrstic;
osamljeni surrogate ostane inline z opombo. Baseline hash odloči vseh pet konfliktnih
primerov; različen dvostranski edit zavrne celoten uvoz. Tipi/odsotnosti/dodatki se ohranijo.

Novi podukazi `/rwcreature unpack clone <tab> <id> <name...>`,
`unpack npc <target> <id>` in `pack <id> <tab> <name...>` zahtevajo level 4.
Shranjeni klon se bere brez cleanTags; živi zajem uporablja obstoječe čiščenje kopije.
Pack upošteva `RwReadableClones=0/1`, ne prepisuje cilja in uspeh vrne šele po tipni
verifikaciji zapisa. Staging je v istem korenu; objava je premik brez replace/atomic
možnosti. Branje je omejeno (clone/source 32 MiB, manifest 512 KiB, mapa 64 MiB),
poti/predniki se preverijo za povezave/junction, Windows imena in prekrivanje.
Če legacy format ne more ohraniti podatka (npr. osamljenega surrogate), pack pri 0
zavrne zapis brez končnega cilja; berljivi format pri 1 ga ohrani. Ni tihe izgube.
To ni dokaz crash transakcije ali obrambe proti sovražnemu procesu, ki sočasno menja prednike.

## Odločitev in meje

**Q546 (19. 11., samostojno):** sledimo c1 iz pogodbe, brez dodatnega stikala ali posega
v živi M15 loader. Ukazi so izrecna administratorska operacija, obstoječa arhitektura D-108
že določa level 4 in nove cilje. Stara uspešna M14 matrika se ne ponavlja: tick/render
koda in njeni scenariji niso spremenjeni. Potrebni so samo zgornji trenutni dokazi.

**Q547 (19. 11., samostojno):** v1 je obstal zaradi zaporedja priprave harnessa:
`DiagChunkLoader.enable` skenira že naložene NPC-je in praznega sveta ne aktivira.
Postavitev WSProbe zato prestavimo pred vključitev ticking pogoja; preverba `stanje=on`
in vsa funkcionalna merila ostanejo. Registriramo v2, v1 ne ponavljamo.

**Q548 (19. 11., samostojno):** v2 je padel pri konstrukciji testnega pošiljatelja,
ne pri workspace ukazu. Prebrani vanilla vir
`dev/build/tmp/recompileMc/sources/net/minecraft/command/CommandSenderWrapper.java`
ima že wrapper, ki izrecno omeji `canUseCommand` na največ podani level.
Uporabimo ga pri 2, brez sprememb classloaderja ali produkcije. Ista permission
preverba potrdi level 2, zavrnjen level 4, uspešen obstoječi `list` in zavrnjen
zapis brez nastanka mape. Registriramo v3, v1/v2 ne ponavljamo.

**Q549 (19. 11., samostojno):** neuspeh v3 je v sestavljanju pričakovanega seznama
PowerShell harnessa, ne dokaz izgube kartic po restartu. Ohranimo iste ključe in
vse stroge preverbe ter popravimo samo tip zbirke z array subexpression `@(...)`.

preverbo hashov. Produkcija, probe JS in JUnit vhodi nespremenjeni; brez ponavljanja
njihovih uspešnih serij (Q90).

**Q550 (19. 11., samostojno):** c1 sprejmemo na podlagi trenutnega v4 in prej uspešnih
nespremenjenih produkcijskih/JUnit vhodov. Ločeno ohranimo odtisa, zavrnjenih v1–v3
