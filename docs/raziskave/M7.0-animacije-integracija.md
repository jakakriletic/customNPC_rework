## 2. Uskladitev verzije (D-024) — statično

Entities mod uvozi iz CNPC samo `EntityCustomNpc` in `EntityNPCInterface` **[K]**. Uporabljeni
CNPC člani: konstruktor `EntityCustomNpc(World)`, polja `ais`, `faction`, `stats`, `display`,
`advanced`; `setFaction(int)`, `reset()`, `DataAI.startPos()/setStartPos(BlockPos)/setWalkingSpeed/
setStandingType`, `Faction.id/isAggressiveToNpc/isAggressiveToPlayer`, `DataStats.setMaxHealth/
hideKilledBody/melee`, `DataMelee.get/setStrength/setRange`, `DataDisplay.setName/setTitle/
setBossbar/setBossColor/getHasHitbox`, `DataAdvanced.setSound`, `bossInfo` ter vanilla overridi.

**[K-javap]** Vsi navedeni člani obstajajo v 01Oct19 (`dev/libs/customnpcs-mapped-01Oct19.jar`) z
istimi deskriptorji. `Faction`, `DataStats`, `DataMelee`, `DataAdvanced` so po podpisih enaki;
05Jul20 doda samo člane, ki jih entities mod ne uporablja (`DataAI` moving path/`IPos` start,
`DataDisplay` markov imena). Razlike v `EntityNPCInterface`/`EntityCustomNpc` so samo SRG↔MCP
imena (repacked jar je SRG, mapped 01Oct19 MCP). **Zaključek [H]:** release jar entities moda
(reobf SRG) je binarno povezljiv z 01Oct19 in z reworkom; potreben je še en zagon v svetu
(povezovanje razredov, M3.x stikala v popravljenem `EntityNPCInterface`, hitbox med animacijo).

## 3. Kje teče integracija

Rework ne sme imeti compile odvisnosti od entities moda (brez njega bitno enak originalu, D-024).
Javni API entities moda, ki ga integracija rabi **[K]**: `EntityAnimatedNpc.playClip(String)`,
`getAction()`, `getActionAge()`, `getActionClip()`, `clipForAction(int)`,
`animations().sortedClipNames()`, `AnimClip.eventsBetween/length/lengthTicks`, zaščiten
`stopAction()`. Klipi imajo **dogodke** (udarec, zvok, tresenje …), ne frameov.

Možnosti: (a) sprememba entities moda, ki kliče most v reworku; (b) most v `rework/anim`, ki
entities mod najde z refleksijo in bere zgornji API. Izbrana **(b)** (Q192): ne posega v tuj repo z
neshranjenim delom, entities mod ostane samostojen, brez entities moda je most neaktiven.

## 4. Hooki (M7.5)

Plan je predvidel `onAnimationStart/End/onFrameEnter/onFrameExit` po zgledu CustomNPC+
(`IAnimationEvent.Started/Ended/IFrameEvent.Entered/Exited`) **[W]**. Entities mod frameov nima,
dogodke pa ima, kar ustreza GeckoLib keyframe dogodkom **[W]**. Odločitev (Q194): hooki
`animationStart`, `animationEnd` in `animationEvent` (ime in tip dogodka, tick v klipu), za JS in
Java po istem registru. Obstoječi `EnumScriptType` se ne spremeni; DataScript dobi pot za imenske
hooke (kot `ScriptContainer.run(String, Object)` **[K]**), Java binder isti registry. Opazovanje
stanja klipa je pod stikalom `RwAnimHooks` (privzeto 0, Q92 brez cenovne meje).

## 5. Script API (M7.9)

Brez spremembe vmesnika `ICustomNpc`: statični vhod `noppes.npcs.rework.anim.Animators.of(npc)`
vrne tipiziran `IAnimator`: `isAvailable`, `play(clip)`, `queue(clip)`, `stop()`, `getClip()`,
`getTick()`, `getClips()` (Q195). `blendTo` → v2: blending je v entities modu klientski s
fiksnimi pravili; zahteval bi nov sync parameter v entities modu.

## 6. Reload (M7.8)

`AnimLibrary` bere klipe samo iz classpatha moda in jih predpomni statično **[K]**. Reload v
igri bi v izdanem jarju znova prebral isto vsebino; smiseln reload zahteva, da entities mod bere
klipe iz zunanje mape (sprememba tujega repa). Predogled brez restarta že pokrije Python preview z
isto matematiko. **M7.8 → v2** (Q196).
